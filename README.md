# Iskra UI

Современная, доступная (a11y) и легковесная библиотека React-компонентов, написанная на TypeScript.

## Установка

```bash
npm install @zelelo/iskra-ui
# или
yarn add @zelelo/iskra-ui
# или
pnpm add @zelelo/iskra-ui
```

**Peer Dependencies:**
Убедитесь, что в вашем проекте установлен React версии 18 или выше:

```bash
npm install react react-dom
```

## Использование

```tsx
import { Button, Input } from "@zelelo/iskra-ui";
import "@zelelo/iskra-ui/styles.css";

function App() {
  return (
    <div>
      <Input placeholder="Введите имя..." />
      <Button variant="primary" size="md">
        Отправить
      </Button>
    </div>
  );
}
```

## Доступные компоненты

На данный момент в библиотеке реализованы следующие компоненты:

- **Accordion** - Гармошка для скрытия/показа контента (поддерживает `single` и `multiple` режимы).
- **Alert** - Цветные блоки для уведомлений (info, success, warning, error).
- **Badge** - Индикаторы (точки или счетчики).
- **Button** - Основная кнопка (primary, secondary, размеры sm, md, lg).
- **Checkbox** - Чекбокс.
- **Input** - Поле ввода (с поддержкой иконок, ошибок и размеров).
- **Modal** - Модальные окна.
- **Radio** - Радиокнопка (с поддержкой состояний ошибки и обязательности).
- **Skeleton** - Заглушки для загрузки контента.
- **Spinner** - Индикатор загрузки.
- **Switch** - Переключатель (тумблер).
- **Tabs** - Табы с поддержкой навигации с клавиатуры.
- **Toast** - Всплывающие уведомления.
- **Tooltip** - Всплывающие подсказки при наведении/фокусе.

## Разработка

Для локальной разработки и просмотра документации используется **Ladle**.

```bash
# Установка зависимостей
npm install

# Запуск локального сервера с компонентами
npm run dev

# Сборка библиотеки в папку dist
npm run build
```

### Линтинг и форматирование

Мы используем:

- **oxlint** + **ESLint** - проверка кода и порядок импортов.
- **oxfmt** - форматирование кода.
- **TypeScript** - строгая проверка типов.

## Правила именования коммитов (Conventional Commits)

Мы строго следуем стандарту [Conventional Commits](https://www.conventionalcommits.org/). Это позволяет автоматически генерировать `CHANGELOG` и понимать историю изменений.

Формат сообщения:
`<тип>(<область>): <краткое описание>`

**Примеры:**

- `feat(button): add loading state`
- `fix(input): resolve focus ring issue`
- `chore(deps): update react to 18.3.1`
- `refactor(core): extract cx utility`

### Разрешенные типы (Type):

| Тип          | Описание                                                       |
| :----------- | :------------------------------------------------------------- |
| **feat**     | Новая фича (добавление нового компонента или пропса)           |
| **fix**      | Исправление бага                                               |
| **refactor** | Рефакторинг кода (без изменения поведения)                     |
| **style**    | Форматирование, пробелы, точки с запятой (не влияет на логику) |
| **chore**    | Рутинные задачи (обновление зависимостей, настройка конфигов)  |
| **docs**     | Изменения в документации                                       |
| **test**     | Добавление или исправление тестов                              |
| **ci**       | Изменения в CI (GitHub Actions, lefthook)                      |
| **wip**      | Work In Progress (временные коммиты внутри ветки)              |

### Разрешенные области (Scope):

Область указывает, какая часть проекта была затронута.

- `accordion`, `alert`, `badge`, `button`, `checkbox`, `input`, `modal`, `radio`, `skeleton`, `spinner`, `switch`, `tabs`, `toast`, `tooltip` - для конкретных компонентов.
- `tokens` - изменения в CSS-переменных и дизайн-системе.
- `build` - настройки сборки (`tsup`, `package.json`).
- `deps` - обновление зависимостей.
- `lint` - настройки линтеров и форматтеров.
- `ci` - настройки пайплайнов.
- `docs` - документация.
- `core` - общие утилиты, хуки, не привязанные к одному компоненту.

> ⚠️ Если вы забыли указать область, или указали несуществующую (например, `feat(foo): ...`), **хук `commitlint` заблокирует коммит**.

## CI / GitHub Actions

В проекте настроен пайплайн непрерывной интеграции (CI) через GitHub Actions.

**При создании Pull Request или пуше в ветку `main` запускаются:**

1.  Проверка линтером (`oxlint` + `eslint`).
2.  Проверка форматирования (`oxfmt --check`).
3.  Проверка типов (`tsc --noEmit`).
4.  Сборка библиотеки (`tsup`).
5.  Сборка статической документации (`ladle:build`).

**Ветка `main` защищена.** Слить код можно только через Pull Request, и только если все CI-проверки прошли успешно. Прямой пуш в `main` запрещен. Слияние происходит через **Squash and Merge** для поддержания чистой линейной истории.
